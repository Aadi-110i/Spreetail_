## ⚡ Concrete Correction Cases

As per the assignment requirements, here are three instances where the AI produced incorrect or incomplete results that required manual intervention.

### 1. Prisma Versioning Incompatibility
- **Issue**: The AI initially suggested using Prisma v7 for the database layer.
- **Problem**: Prisma v7 introduced breaking changes to the `datasource` URL configuration that caused runtime errors in the specific local environment.
- **Correction**: Manually downgraded to Prisma v6.19 and re-initialized the database to ensure stability.

### 2. Configuration File Conflict
- **Issue**: The AI generated a `prisma.config.ts` file in the root directory.
- **Problem**: Next.js and Prisma v6 were already configured to use `prisma/schema.prisma` natively; the extra config file caused a conflict that prevented the Prisma Client from generating correctly.
- **Correction**: Deleted the redundant `prisma.config.ts` and restored the standard Prisma project structure.

### 3. Missing Temporal Logic in Splits
- **Issue**: The initial CSV splitting logic generated by the AI split expenses among all group members regardless of the expense date.
- **Problem**: This violated Sam's requirement (the "temporal join-date" rule). Sam joined on April 15th and should not have been charged for any March or early April expenses.
- **Correction**: Manually implemented a `KNOWN_MEMBERS` join-date map in `csv-parser.ts` and added an error check to flag any transactions where a member was charged before their join date.
